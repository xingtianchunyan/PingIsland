## 一、特质/技能库（ContentLibrary）

- **72 项内容**：12 模板（6 元素 × 主动/被动）× 6 稀有度变体，含名称、描述文案、图标键、主动演出姿态键
- **配套键映射**：装备 4 部位 × 4 外观（布/皮/铁/机甲）共 16 个图标键、8 职业立绘键、疲劳 5 阶段键、夜间休眠键、3 怪物键、App 图标键
- 数值规则**不重复实现**：被动数值仍由 `SkillRules.passiveValue` 推导，本库只做内容与展示定义（遵守执行文档"单一实现来源"）
- `ContentLibrary.isValid` 与测试共享同一校验：模板名/被动属性与 `SkillRules.template(forWeekday:)` 强一致——若改规则名，JSON 同步改，否则测试失败

### 合入步骤

1. 拷贝 `Sources/PingIslandKit/ContentLibrary.swift` 与 `Resources/ContentLibrary.json` 进 `PingIslandKit/Sources/PingIslandKit/`
2. 用交付的 `Package.swift` 替换现有（差异：`defaultLocalization`、target `resources: [.process(...)]`、testTarget 同样带 resources）
3. 拷贝 `ContentLibraryTests.swift` 进 `Tests/PingIslandKitTests/`
4. Windows `swift test` 或 CI 验证：新增 11 个测试，预期 97 + 11 = 108 通过
5. 注意：`Bundle.module` 由 SwiftPM 生成，规则不变；App 侧引用图标名经 `ContentLibrary.shared` 查询

### 收藏页接入示例

```swift
let lib = ContentLibrary.shared
if let item = collectionItem {   // SkillCollectionItem
    let kind: SkillKind = item.isActive ? .active : .passive
    if let variant = lib?.variant(weekday: item.weekday, kind: kind, rarity: item.rarity) {
        Text(variant.name)                  // 如 "火焰学识·灼见"
        Text(variant.desc)                  // 文案
    }
    if let icon = lib?.skill(weekday: item.weekday, kind: kind)?.iconKey {
        Image(icon)                         // Assets.xcassets imageset
    }
}
```

展示降级：`ContentLibrary.shared` 为 nil 时回退现有 SF Symbol 占位（`Image(systemName:)`），不影响结算。

## 二、美术资产

风格：Q 版卡通、厚描边、软色阶；角色 45 张全部由同一基础角色参考图派生，保证同一张脸。

| 类别 | 数量 | 命名 | 用途 |
|---|---|---|---|
| 职业立绘 | 8 | `class_bard` 等（对应 `classArtKeys`） | 角色主页/卡片职业姿态 |
| 疲劳关键帧 | 5 | `fatigue_fresh / tired / drowsy / leaning / sleeping` | 10.2 疲劳五阶段展示 |
| 夜间休眠 | 1 | `pose_night_sleep` | 23:00–06:00 故事睡眠姿态 |
| 技能图标 | 12 | `skill_wood_active` 等 | 收藏页/日记/灵动岛最近技能 |
| 装备图标 | 16 | `eq_head_cloth` 等（部位×布/皮/铁/机甲） | 装备栏（稀有度用边框色叠 加） |
| 怪物 | 3 | `monster_skeleton / goblin / slime` | 遭遇展示 |
| App 图标 | 1 | `AppIcon.appiconset` | 替换现有占位图标 |

### 合入步骤

1. 将 `Assets/Assets.xcassets` 整目录合入主 App `Resources/`（替换现有只有 AppIcon 的 xcassets）
2. `project.yml` 中主 App target 的 sources 已含 Resources 目录，XcodeGen 重新生成即可
3. Widget 扩展若要使用角色关键帧，把对应 imageset 同步加进 Widgets target 的 resources（灵动岛紧凑态建议只放 `class_*` 与 `fatigue_*`，768px 原图可下采样到 3x @200px 左右控制包体）
4. 图片均为不透明 PNG（AI 生成不带 alpha）；如需透明背景，可用抠图批处理（remove-bg 类工具）后替换 raw 同名文件

### UI 接入要点（对应执行文档）

- 角色主页：`classArtKeys[职业]` 立绘 + `fatigueArtKeys[阶段]` 小图，替换现有 `person.fill` 占位
- 装备栏：`equipmentIcon(slot:tier:)` 取图；稀有度以叠层描边色表达（白/绿/蓝/紫/橙/红 → 系统色 `gray/green/blue/purple/orange/red`）
- 灵动岛紧凑态（摄像头侧约 60pt）：使用 `class_*` 图下采样，保持静态关键帧（11.3 不承诺动画）
- `pose_night_sleep` 由 `PresentationPolicy` 判定夜间时优先展示（11.4 展示优先级）
- 外观等级换装逻辑：`EquipmentAppearance` tier → `AppearanceTier` 映射：布甲=cloth、皮甲=leather、铁甲=iron、机甲=mech

## 三、已知限制

- 本沙箱无 Swift 工具链：Swift 侧未本地编译，结构与规则一致性已用脚本静态校验（12 模板/72 变体/键唯一），请在 Windows `swift test` 或 CI 确认 108/108
- 美术为 AI 生成 Q 版统一风格，适合占位到中等品质；替换素材时保持同名 imageset 即零代码改动
- 扩展到 174 项内容池：往 `ContentLibrary.json` 的 `skills` 增加新模板即可，`isValid`/测试会自动约束结构（若放宽 12 模板上限需同步改测试）

## 四、v2.1 更新（本次打包新增）

- **透明底**：45 张主图（技能/装备/怪物图标 + 角色关键帧）已全部去除纯色背景（边缘泛洪抠图 + 1.5px 羽化，保留物品内部白色），RGBA PNG，可直接叠放在任意底色/渐变上（万智牌卡画框、灵动岛紧凑态等）
- **Widget 变体**：每张主图附带 `<key>_widget` 小图 imageset（图标 240×240、角色 360×540），供 Widget/Live Activity 扩展 target 使用，控制扩展包体与解码内存；主 App 继续用原键名
- AppIcon 不做透明处理（iOS 规范要求不透明）

Widget 接入示例：
```swift
// Widgets target 内
Image("class_bard_widget")   // 小尺寸卡片
Image("fatigue_fresh_widget") // 疲劳关键帧
```
